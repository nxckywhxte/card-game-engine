# ADR-003: Контракт Comparable включает isFaceUp

**Статус:** Принято  
**Дата:** 2026-08-31

## Контекст

`Card` реализует `Comparable<Card>`. Поле `equals()` в `record` учитывает
все три поля: `suit`, `rank`, `isFaceUp`. Возник вопрос: должен ли `compareTo`
тоже учитывать `isFaceUp`, чтобы соблюсти контракт `compareTo == 0 ⇔ equals`?

## Решение

`compareTo` сравнивает карты по трём полям последовательно:
1. `rank` (достоинство)
2. `suit` (масть)
3. `isFaceUp` (состояние: закрытые раньше открытых)

Это обеспечивает полную согласованность контрактов `java.lang` и корректную
работу со всеми стандартными коллекциями (`TreeSet`, `TreeMap`, `Collections.sort`).

## Важное уточнение

Метод `compareTo` определяет **естественный порядок сортировки**, а не правила
сравнения в конкретных играх. Например, в Дураке красный джокер бьёт только
красные карты — эта логика реализуется в модуле правил (`engine-rules-durak`),
а не в `core`.

## Последствия

### Положительные
- Полная согласованность с контрактами `java.lang`
- Корректная работа `TreeSet`, `TreeMap`, `Collections.binarySearch`
- Предсказуемое поведение при сортировке

### Отрицательные
- Логически немного странно, что закрытая карта "меньше" открытой
- Для сортировки без учёта `isFaceUp` нужен отдельный `Comparator`

## Альтернативы

1. **Игнорировать `isFaceUp` в `compareTo`** — нарушает контракт, ведёт к потере данных в `TreeSet`
2. **Убрать `Comparable` из `Card`** — менее удобно для стандартных коллекций
