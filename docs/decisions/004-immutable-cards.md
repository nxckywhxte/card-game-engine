# ADR-004: Карты неизменяемы

**Статус:** Принято  
**Дата:** 2026-08-31

## Контекст

Нужно было решить, делать ли карты изменяемыми (как обычные классы с сеттерами)
или неизменяемыми (как `record`).

## Решение

`Card` реализован как **неизменяемый `record`**. Все операции, которые
"изменяют" карту (например, переворот), возвращают **новый экземпляр**,
не изменяя исходный.

## Последствия

### Положительные
- **Потокобезопасность**: карты можно безопасно передавать между потоками
- **Предсказуемость**: карта не может неожиданно измениться
- **Безопасное кэширование**: карты можно хранить в коллекциях без риска
- **Простота отладки**: состояние карты фиксируется в момент создания

### Отрицательные
- Создаётся больше объектов при частых "изменениях" (переворотах)
- Для игровых состояний тоже нужно применять иммутабельный подход

## Альтернативы

1. **Изменяемый класс с сеттерами** — риск гонок данных и неожиданных изменений
2. **Копирование через конструктор вручную** — менее удобно, чем `record`

## Применимость

Этот принцип распространяется на все сущности библиотеки:
`Card`, `GameState`, `Move` и другие должны быть неизменяемыми.
