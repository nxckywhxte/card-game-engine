# ADR-001: Проект является библиотекой, а не приложением

**Статус:** Принято  
**Дата:** 2026-08-31

## Контекст

Нужно было решить, что именно разрабатывать: готовое приложение с карточными
играми или переиспользуемую библиотеку (движок).

## Решение

Разрабатываем **библиотеку** (движок карточных игр). Конечные приложения
(консольное, веб, мобильное) будут созданы в отдельных проектах-потребителях.

## Последствия

### Положительные
- Библиотека переиспользуется в любых приложениях
- Чёткий публичный контракт заставляет продумывать интерфейсы
- Стабильность API повышает ценность проекта в резюме
- Модульная структура позволяет развивать каждую игру независимо

### Отрицательные
- Нужно больше внимания к обратной совместимости
- Нет готового "запускаемого" продукта в этом репозитории
- Требуется отдельный проект-демонстрация

## Альтернативы

1. **Монолитное приложение** — проще, но не переиспользуется
2. **Фреймворк с плагинами** — сложнее и избыточно для текущих целей
